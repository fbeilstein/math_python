\textbf{Key concept:} PyTorch tensors behave like NumPy arrays, but they remember every operation applied to them. Calling \lstinline|loss.backward()| automatically computes derivatives of \lstinline|loss| with respect to all tensors that have \lstinline|requires_grad=True|. This is how we differentiate \emph{through} the split-operator simulation.


\section*{Task 1: Differentiable SSFM}

\subsubsection*{Mathematical part}
You have previously built a split-operator solver (QM Problem 5). In standard numerical methods, we compute the wave function $\psi(x,t)$ given the potential $V(x)$. This is the \emph{forward} problem. 

To solve the \emph{inverse} problem---finding $V(x)$ from $\psi(x,t)$ observations---we will treat the split-step Fourier method as a computational graph and differentiate through it. 
Recall the Trotter splitting for a single time step $\Delta t$:
$$
|\psi(t + \Delta t)\rangle \approx e^{-i\hat{V}\Delta t/(2\hbar)} e^{-i\hat{T}\Delta t/\hbar} e^{-i\hat{V}\Delta t/(2\hbar)} |\psi(t)\rangle
$$
Because all operations involved (multiplication by complex exponentials, FFT, IFFT) are differentiable, we can rewrite this sequence entirely in PyTorch. The framework will automatically keep track of the operations and build a gradient graph.

\subsubsection*{Implementation part}
\textbf{Implement:}
1. \lstinline|pt_split_operator_step(psi, k_sq, V, dt)|: Implement one Trotter step using PyTorch operations. Ensure you use \lstinline|torch.fft.fft| and \lstinline|torch.fft.ifft|. Do \textbf{not} call \lstinline|.numpy()| anywhere inside this function, as it will break the computational graph.

\section*{Task 2: Learnable Potential}

\subsubsection*{Mathematical part}
Now imagine you are an experimentalist: you observe a wave packet scattering off an \textbf{unknown} potential $V_{\text{true}}(x)$. We want to find a $V_\theta(x)$ that produces the same scattering dynamics.

Instead of representing $V_\theta(x)$ as an abstract function, we represent it as a trainable 1D array of values at our grid points. However, blindly optimizing 512 independent values often leads to a noisy, non-physical potential full of high-frequency "ringing". 

To prevent this, we represent the potential as a raw parameter vector $V_{\text{raw}}$, and we apply a Gaussian smoothing kernel before using it in the simulation:
$$
V_\theta(x) = (V_{\text{raw}} * \kappa)(x)
$$
where $\kappa$ is a discrete Gaussian kernel.

\subsubsection*{Implementation part}
\textbf{Implement:}
1. The \lstinline|__init__| method is provided for you to save you from writing PyTorch boilerplate. Notice how it creates a \lstinline|torch.nn.Parameter| initialized to zero, and creates a 1D Gaussian kernel registered as a buffer (so it moves to the correct device but is not trained).
2. \lstinline|GridPotential.forward(self)|: Apply \lstinline|torch.nn.functional.conv1d| to your raw parameter using the Gaussian kernel, and return the smoothed potential.

\section*{Task 3: Teacher Forcing}

\subsubsection*{Mathematical part}
Given sparse observations $\{|\psi(x_j, t_k)|^2\}$ at various times, we want to find $V(x)$ such that propagating $\psi_0$ through $V$ reproduces the observations.

Naively unrolling the simulation for hundreds of steps and backpropagating the final error causes \emph{cycle skipping} --- if $V_\theta$ is slightly wrong, the predicted wave shifts out of phase with the true wave, and the gradient points the wrong way. The loss landscape is highly non-convex.

The fix is \textbf{Teacher Forcing}: break the trajectory into short segments (e.g., 10 steps). At the start of each segment, \textbf{reset the simulation to the true state}. We only predict the wave evolution over a short horizon. This bounds the maximum phase error and ensures the gradients always push the parameters in the correct direction.

\subsubsection*{Implementation part}
\textbf{Implement:}
1. \lstinline|run_teacher_forcing(V_pred, psi_observations, psi0, k_sq, dt)|: Loop over the consecutive pairs of snapshots. For each pair $(i, i+1)$, set the state to the true $\psi_i$. Evolve it forward using your \lstinline|pt_split_operator_step| and $V_{\text{pred}}$ until the time matches $i+1$. Compute the Mean Squared Error against the true $\psi_{i+1}$ and accumulate it. Return the total loss.

Once you have implemented these functions, run \lstinline|python lab_dashboard.py|. You will see the optimization process live: the predicted potential will slowly converge to the hidden $V_{\text{true}}$.
